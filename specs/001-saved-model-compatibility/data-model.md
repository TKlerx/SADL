# Fixture data model

| Entity | Fields and constraints |
| --- | --- |
| Training input | Small, fixed timed sequences in the standard CLI input format. Shared by model training and the detector training argument. |
| Evaluation input | Fixed timed sequences with normal and anomalous labels. Shared by both positive paths. |
| Fresh model | Nonempty output from the current `train` process, stored in a temporary directory and passed to a separate `test` process. |
| Reference model | Read-only artifact generated by the baseline CLI. Record revision, JDK, training input and exact train/test options beside it. |
| Evaluation oracle | Fixed true-positive, false-positive, true-negative and false-negative counts from the verified baseline. Counts must account for every evaluation sequence. |
| Unusable stand-in | Temporary replacement bytes used to show that the same evaluation assertions fail. |

Lifecycle: capture the reference once, then reuse its bytes. Each validation run creates its own fresh model and result files. Only temporary copies may be altered for the red check.
